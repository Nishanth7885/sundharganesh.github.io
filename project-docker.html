Containerized Infrastructure Management with Docker and Portainer

Replaced bare metal services with containers and gave the team a single pane of glass for multi host container management.

Docker Portainer Jenkins MySQL phpMyAdmin Linux

Executive Summary

Containers as the New Default

G. Kuppuswamy Naidu Memorial Hospital

Internal supporting services used to run directly on host machines with hand crafted configuration. That made every host a snowflake and made changes risky. I configured Docker on multiple Ubuntu servers and brought them under one Portainer instance so the team could manage containers across hosts from one screen, without having to SSH everywhere.

Docker on multiple hosts
One Portainer pane of glass
Jenkins, MySQL, phpMyAdmin containerized

The Problem

  • Internal services ran on bare hosts with inconsistent configuration.
  • Standing up a new instance of any service meant reading old notes and hoping they were current.
  • There was no unified way to see what was running across the fleet.
  • Restarting or upgrading a service depended on whoever set it up originally.

What I Built

1. Standardized Docker on Ubuntu hosts

Installed Docker on each target host with a consistent setup, log rotation, and a sensible daemon configuration so containers behave the same way across the fleet.

2. Centralized management with Portainer

Stood up Portainer as the management plane and added each Docker host as an endpoint. Now the operations team can inspect, restart, and update containers across multiple hosts from one UI, without needing SSH on every box.

3. Containerized internal services

Moved Jenkins, MySQL, and phpMyAdmin onto Docker. Each service is now defined declaratively, comes with its own isolated environment, and can be torn down and rebuilt without touching the host.

4. Container lifecycle management

Established conventions for image tagging, volume backups, and service restart policies so the platform behaves predictably under load and across reboots.

5. Isolation and networking

Worked through container networking and isolated environments so internal services do not step on each other. This made it safe to run multiple Jenkins instances and database stacks on the same hosts.

Outcome and Impact

  • The internal platform is reproducible. If a host dies, we redeploy the containers, not the OS configuration.
  • Operations stopped needing tribal knowledge to manage internal services.
  • Jenkins, MySQL, and phpMyAdmin became boring services that anyone on the team can restart.
  • Gave the CI/CD project a container runtime it could rely on from day one.

What I Learned

  • Docker + Portainer is a strong stepping stone before Kubernetes. The hospital does not need orchestration at K8s scale, and Portainer fills the gap pragmatically.
  • Backups are about the volumes, not the containers. Treat the container as cattle, the data volume as the pet.
  • A pane of glass changes behavior. Once the team could see everything at a glance, they started fixing things they previously did not know existed.
